## 项目范围与我的工作方式

这是自己的 AI 网站，后端使用 Spring Boot 和 MySQL，前端使用 Vue 3 与 TypeScript。产品包含聊天、图像与视频生成、漫剧、静态漫画、穿搭视频、积分管理和生成任务中心。

代码大量由 AI 生成和修改。我负责提出功能需求、梳理使用流程、确定计费与任务规则，检查实现与页面行为，并根据具体问题继续修改。下面记录可以从提交、源码和已有测试对应起来的工作事项。

## 模型接入：能力、参数与服务商协议

后端分别管理服务商、模型、密钥和能力配置。生成请求带能力、模型 ID、提示词及参考素材等参数，服务端加载启用的模型和密钥，再通过适配器调用服务商。密钥解密留在后端，前端只取得可选模型与能力信息。

聊天、图像和视频的请求方式不同。视频还需要约束时长、比例与参考素材，避免页面显示的选项超出模型支持范围。个人提交包括 Bafang Sora、Veo、Omni 模型适配，以及视频参考素材校验；当前工作区的后续模型和异步图像扩展另有未提交内容，不计入以下已提交记录。

## 聊天积分：预扣、结算与退款

2026 年 7 月的修复针对按 Token 计费的预扣结算。调用前估算输入量与最大输出量，按模型的输入、输出费率计算预扣金额，并约束传给服务商的最大输出。余额不足时在外部调用前拒绝。

AiRequestService.settleBilling 按以下规则处理：

| 返回情况 | 积分处理 |
| --- | --- |
| 有 usage，计算费用低于预扣 | 按实际费用结算，退回差额 |
| 有 usage，计算费用高于预扣 | 结算金额限制为预扣金额，返回已生成结果 |
| 没有 usage | 按配置的回退费用结算 |
| 服务商抛错或返回失败 | 对关联交易执行退款，并记录失败状态 |

CreditService 对交易与余额加行锁，退款遇到已经退款的交易直接返回。已有测试覆盖结算超过预扣上限、usage 缺失、调用失败和账本余额一致性。输入 Token 估算仍是估算，不是服务商账单的精确预报。

## 视频任务：从浏览器等待改为后端持续跟踪

视频请求通过 /api/ai/jobs 创建本地任务，以用户和 requestId 查重，记录请求、交易与初始状态。后台领取任务并提交，获得服务商任务 ID 后继续轮询；任务中心查询本地记录，展示结果或错误。

已提交实现使用 PENDING、SUBMITTING、PROVIDER_PROCESSING、SUCCEEDED、FAILED、CANCELLED 状态。提交与轮询使用不同线程池和并发槽位；租约与令牌用于领取及结果更新，防止旧工作线程覆盖新的处理结果。

页面关闭后，已经创建的任务由后端继续跟踪。取消只适用于还没有提交到服务商的任务。服务商已经受理而本地还没保存任务 ID 时，本地查重与租约也不能单独保证外部只生成一次。

已有任务测试覆盖同请求只建一个任务、活动任务数量限制、待提交取消退款、用户隔离、旧轮询租约回写和模型禁用后的任务处理。本次整理没有重新运行这些测试。

## 漫剧与静态漫画：生成前检查项目输入

漫剧把项目、分镜和生成素材组织起来。预检接口按项目与选中的分镜检查输入，拒绝重复分镜 ID，验证归属，并返回错误与警告数量。已有有效素材的分镜可跳过对应检查；只有错误数量为 0，预检响应才允许继续。

静态漫画工作台已有独立服务、页面和数据表迁移。近期漫画页面布局、批量并发和导出流程仍有未提交修改，因此这里只记录已提交的工作台。

## 存储与发版维护

维护中有三类具体修复：清理请求审计里的 Base64 图片数据；避免浏览器历史重复保存图片内容；发布后旧页面请求不到懒加载资源时，增加恢复处理。它们分别涉及后端审计、浏览器存储和前端资源版本。

这些修复保留在提交和对应服务、测试中。浏览器生成结果与后端任务元数据的保存位置不同，页面历史不等于所有素材都有后端长期备份。
