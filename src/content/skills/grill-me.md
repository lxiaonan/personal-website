## 它是干什么的

`grill-me` 让 AI 扮演一个持续追问的讨论伙伴，帮助你检查计划、设计或想法是否真的想清楚了。“Grill”在这里可以理解为深入盘问：不满足于“做一个好用的功能”，而是继续确认谁会用、在什么场景用、成功标准是什么、哪些情况不在本次范围内。

它适合产品想法、学习计划、个人决策，也可以辅助技术方案讨论。当前上游的 `grill-me` 是一个入口，会调用共享的 `grilling` 能力来组织访谈。

## 它如何帮助你思考

它会把方案看作一棵决策树：先讨论已有前提下能决定的问题，再根据你的回答进入下一层。当前版本可以在一轮中询问多个互不依赖的问题，并为每个问题提供推荐答案；依赖尚未确定条件的问题会留到后面。

例如“给个人网站加 AI 功能”会被拆为：服务谁、解决哪个具体问题、需要哪些数据、接受多长响应时间、是否允许登录、如何判断上线后有用。你不需要一次写完整需求，但需要对关键取舍作出选择。

## 安装与依赖

```bash
npx skills add mattpocock/skills
```

在选择界面选中 `grill-me` 和它依赖的 `grilling`。安装整个技能包也可以。当前版本的入口文件很短，单独复制 `grill-me/SKILL.md` 可能漏掉真正执行访谈的共享能力。

## 推荐调用方式

```text
使用 grill-me 帮我推敲这个想法：
我想给 Java 后端个人网站增加一个 AI Skills 栏目。
目标读者是刚开始使用 AI 编程的开发者，希望读完能选对 Skill 并完成第一次调用。
请重点追问内容范围、阅读路径、维护成本和验收标准。
每轮给出你建议的选择，并等我回答后再继续。
```

在支持斜杠调用的 Agent 中，也可以使用 `/grill-me`。具体入口名称以安装后的技能列表为准。

## 怎样回答才更有效

1. **给出真实约束。** 例如“两天内完成”“只维护静态网站”“读者没有命令行基础”。
2. **用具体场景回答。** “用户看完能复制命令、安装成功并知道如何调用”，比“体验要好”更容易验收。
3. **允许保留未知。** 不确定的地方可以先标为假设，并明确用什么方式验证。
4. **结束时整理结论。** 要求输出目标、必做项、不做项、已确认决策、风险和下一步。

## 预期产出

一次有效讨论的结果，是双方对目标和取舍形成共同理解。例如明确栏目要介绍哪些 Skill、谁负责更新、安装示例是否需要验证，以及什么条件下算完成。建议最后让 AI 输出一页可执行的需求摘要，方便转交给实现阶段。

## 与 grill-with-docs 怎么选

临时讨论、个人计划或一次性决策，优先用 `grill-me`。如果讨论围绕一个长期维护的代码库，需要把业务术语和重要架构决策写进项目文档，则更适合 `grill-with-docs`。

`grill-me` 本身不等于产品验证。讨论能够揭示假设，但真实用户是否需要该功能，仍然要通过反馈、原型或实际使用确认。也不要把访谈当作已经授权开始编码；讨论结束后应先确认整理出的方案。
